# RAG Agent：最终实施与评测计划

定稿日期：2026-11-09。**数据、离线评测及统一执行控制已实现；新数据集上的回答质量尚未测量。** 下一轮以最终回答/行为为验收依据，阶段指标用于解释失败。本轮无付费调用、数据库改动或GitHub发布；仅显式启用执行控制阈值，检索/生成设置不变。

## 1. 当前起点

已完成LangGraph单协调Workflow：`原问/背景 → catalog → Planner → retrieve → fusion → rerank/context → evidence_gate → answer → validate`。有澄清/资料不足分支、类型化终态、来源span、CLI/API/Trace Studio、共享计费账本及节点/调用上限；计算、BM25替换、CrossEncoder、任务重组默认关闭。

尚缺语义证据充分性判断、自动补查及已校准的行为/回答质量实测；技术失败已支持可见的纯证据兜底。gate目前仅判断context是否为空；引用ID/结构有效不等于数字或支持关系正确。持久恢复、多Agent、实时行情、预测/估值暂不加入。

课程依据：第10章的State/Decision/Action、受控工具和终止；第11章的原问与改写分离、来源保留、证据/拒答及分阶段评测。继续使用LangGraph，不为套用ReAct而添加循环。

## 2. 输入边界与用户可见行为

先根据已声明能力、已发布目录与实际用户上下文判断；尽量并入现有Planner，不为每条问题再增一个独立LLM分类器。模型不能授权新工具、下载外部数据或扩大检索范围。

| 情况 | 应有行为 | 不能做什么 |
| --- | --- | --- |
| 问题清楚、资料支持 | 检索并回答，保留公司/期间/单位/来源 | 用参数记忆填财务数 |
| 缺公司/期间/指代，或确认条件冲突且影响答案 | 只问必要条件，第一轮以澄清终止 | 偷补“最新三年”、读离线潜在映射，重复问已明确条件 |
| 与年报研究无关，如天气/旅游 | 说明当前范围不支持，并提示支持的年报任务 | 调用财报检索凑答案，或虚称金融政策禁止 |
| 金融领域但当前能力未实现，如实时股价、预测/估值 | 明确缺的能力/数据；可提供当前支持的年报分析 | 伪装已接行情/估值工具；将所有投资问题一概当业务外 |
| 公司/报告未入库 | 说明库未覆盖，列出缺的公司/报告；用户可选择已覆盖范围或另行入库 | 自主联网下载；把无语料等同技术故障或业务外 |
| 在库但未充分披露，如完整季度序列/市场份额 | 说明具体缺口与所需口径，有支持的部分先回答 | 猜数字、年收入均摊季度或两家收入比例冒充市场份额 |
| 混合请求，部分支持、部分不支持 | 按子目标回答/澄清/说明限制，不整体拒绝 | 为简化路由丢掉可答部分 |
| DB/provider失败、预算耗尽、取消/超时 | 明确运行终态及已完成范围，保留trace | 伪装成“年报没披露”或正常拒答 |

路由动作、原因码、用户可见说明分开；当前Plan只有retrieve/clarify/insufficient，以上细分仍需兼容性实现，不能仅靠更换提示语冒充已支持。无需用通用拒答掩盖不确定性。

澄清先按一次请求结束。后续用户补充与原问一起形成新的、经过验证的Request，并关联前次run；不能把服务端猜测当用户确认，也不要求为此先建设长期记忆。用固定的真实补充输入单独测试“澄清后恢复”。

## 4. 评测框架与指标

**技术选择：现有`finrag.evaluation + pytest + 本地trace + 离线Judge`。** RAGAS作为按需指标适配，不更换Agent框架、不引入第二套平台。所有指标定义、公式、分母、N/A和标签要求以[评测契约](evaluation.md#evaluation-contract)为唯一说明。

| 层 | 默认指标 | 作用 |
| --- | --- | --- |
| 最终行为/回答 | Task success与执行覆盖；五维rubric；必答事实/数字覆盖；输出数字正确率；引用支持/覆盖；重大错误 | 验收改进；不能用一个均分掩盖未交付、拒答或错误数字 |
| 路由/澄清 | 行为正确率、澄清P/R、不必要澄清率、错误拒答率、分类型边界遵守、澄清后恢复 | 检查是否该答、该问、只能部分答；不是所有不生成都失败 |
| Planner | 意图覆盖、无依据新增目标、约束保留/漂移 | 判断改写/拆解是否改变了原意 |
| 检索/粗排/Context | 候选池/Top10/20/80证据组Recall、Top80保留率、最终实际context Recall、空结果率 | 找到损失发生在哪层；不当作答案正确率 |
| 排序补充指标 | MRR；Precision/nDCG/Context Precision/事实级Context Recall仅在相应标签齐备后启用 | 未标chunk不当负例；暂缺标签就N/A，不为填看板付费 |
| 执行 | 调用/attempt/cache、token/费用/预留、耗时及经验p95、重试/修复和失败终态 | 成本/可靠性诊断；小样本不宣称生产p95/RPS |

统一评测流：`已确认标签 → runner/replay → 真实trace → 行为/阶段规则 + 数值/引用校验 + Judge → 逐题results → 配对报告/bad cases → 回归`。保存manifest与代码/config/Prompt/模型/索引/数据身份；未执行、失败、待判不能静默丢弃。五维各自单报，不换算一个虚构总正确率。

先用6份历史回答及少量受控错误夹具校准Judge；精确摘录/hash只保证可审计，不保证Judge判断正确。人工复核所有重大错误与分歧。基线/候选盲评、同rubric/同预算，报告逐题退步。规范题vs raw表达对照与同一raw输入的直搜vs Planner消融是不同实验；固定计划只作诊断上界，不能给在线Planner喂gold子问题。

## 5. Bad cases与Trace工具

**每个bad case都分析trace。** 运行失败、错误路由、重大错误、回归、Judge争议全部收集，另取少量成功对照；记录期望/实际、首个可观察偏差、相关原文/span/代码、假设原因、验证办法及修复后的同题结果。

按“资料发布/可得 → 范围/needs → 候选 → Top80 → 精排/实际context → 生成/计算 → 引用/输出”检查。完整候选中没有证据，不能直接归咎于embedding；也要查范围、解析和索引。用冻结上游的重放作验证；历史compact trace缺内容时注明无法归因。

**本轮保留本地Trace Studio，LangSmith为可选适配，不作前置条件。** 当前已有节点/阶段I/O、父子span、代码位置、模型使用和账本；补上评分/失败分类到同一run的链接即可。云端以后显式启用，保留同一ID、脱敏、失败隔离和关闭开关，不重新实现trace产品，也不自动上传原始本机材料。SDK已是依赖，但runner当前显式关闭云端tracing；仅设环境变量不能自动接好自定义DeepSeek/SQL跨度。

官方LangSmith支持LangGraph追踪、离线/在线评测及span级人工反馈；有免费Developer额度，但超量、保留和模型Judge另算，故不以“接平台”替代评测契约或假设零费用。[追踪](https://docs.langchain.com/langsmith/trace-with-langgraph) · [反馈](https://docs.langchain.com/langsmith/annotate-traces-inline) · [价格](https://www.langchain.com/pricing)。

## 6. Orchestrator与执行策略

复用`RunPolicy / RunControl + 唯一Budget账本`。不创建第二套orchestrator或金额账本。逻辑调用、cache命中和真正外部attempt分开统计。

| 控制 | 当前实现（2026-11-09） |
| --- | --- |
| 单请求调用 | 节点≤16、逻辑LLM调用≤32、实际provider请求≤64、搜索SQL attempt≤192。embedding/CE计入provider次数；缓存命中不计新API请求。修复及重试共用总额 |
| Attempts | Planner/回答各≤1次结构修复，精排每批≤1次；全请求SQL确认超时最多恢复1次；仅连接未建立的重试可配置≤1次，默认0；图不自动重试 |
| 时间/取消 | 单请求180秒，从资源初始化前计时；HTTP各阶段timeout及搜索SQL timeout取原上限与剩余时间的较小值。缓存/批次/搜索/修复之间检查取消；流断连、显式取消及CLI Ctrl-C均传递信号 |
| 金额 | 请求上限$0.15；非回答付费操作前在唯一账本预留$0.04答案额度。回答开始时在同一文件锁内换成真实调用预留；不生成回答的请求不留答案额度。配置值是工程护栏，不是实测报价或质量门槛 |
| 共享账本 | 2026-11-12按用户授权纠正过期$1.60停止线：当前共享上限$4.90，另留$0.10覆盖旧embedding账本，总额不超过$5；已结及未结费用均保留。`evaluation run --batch-usd`可加独立批次上限，同输出目录续跑累计已花/未结金额，不能静默调高批次限额 |
| 未知计费 | 读取超时、HTTP错误、缺usage等不重发、不释放实际调用预留。已知usage先结算，即使调用中取消/超时也保留真实费用；只释放未使用的policy预留 |
| 兜底 | 技术/格式/预算失败保留失败终态与错误码。有已选证据时默认返回`fallback.type=evidence_only`及证据ID，明确未生成答案；可配置`none`。取消/超时不继续生成，也不提供自动兜底答案。澄清/资料不足仍走原分支 |
| 未启用 | rerank退化到粗排、换provider、语义补查、自动上网、持久恢复；本轮不改QueryPlan、Top-k、融合、精排、上下文上限或模型prompt |

**入口与查证**：`serving/runtime.py:query`建立trace/control后创建资源，`agent/runner.py`绑定同一control调用图，`agent/policy.py`管理计数/时限；`providers/llm.py:Budget/PaidClient`管理唯一金额账本与实际HTTP尝试；`retrieval/store.py:search`管理SQL尝试。结果在`agent.outcome`、`agent.usage`、`agent.transitions`、`duration_seconds`及`fallback`中查看；Trace Studio代码地图新增execution_policy和resource_setup入口。

取消接口：`POST /queries/{query_id}/cancel`只作用于本进程活动请求，返回“已请求取消”，不代表provider已撤销。SSE返回accepted后可获query_id；流断开也会设置同一信号。并发槽保留到worker真正完成；服务正常关闭会发取消并等待清理。CLI Ctrl-C同样停止后续步骤。

**边界**：这是协作式取消/截止时间，不能硬中断已发送的同步HTTP或SQL，HTTP分阶段timeout也不是总墙钟强制中断。已返回的响应先结算，再拒绝交付迟到答案；硬崩溃时未结预留保留以便核账，不自动当作免费。`duration_seconds`覆盖资源初始化到清理，排除准入等待、trace落盘与网络传输；旧trace无法补算该字段。未进行真实provider故障、性能负载或新财务答案质量验收。

## 7. 实施顺序与验收

1. **数据与契约**：将review修订形成可确认的小批标签，补6类边界及R08–10后续输入；用户确认后再冻结。原24条参考/Mock不是模型实跑结果。
2. **离线评测框架**：补行为评分、阶段抽取、统一结果与配对报告，复用数字/Judge模块；用保存回答/固定工具回执和受控错误验证评分器，不调用模型。
3. **执行策略（已实现并离线验证）**：统一attempt/金额/时间/取消和可见终态；下一步用已授权的小集观察实际分布，不能靠放宽限制提高分数。
4. **后续付费基线**：先6条覆盖回答、跨公司/时点、澄清、缺披露、范围外的已确认案例；按需测同题一个候选，再补其余案例。每次固定选择及预算；没有全量执行就不写“30题成绩”。
5. **定位与优化**：先Planner/过滤、排序/context或generation的实际错误；先保持chunk/index不变。必要时才独立对比BM25/CE、计算或一次补查。保留逐题退步；候选锁定后再测独立holdout。

晋升要求：冻结的同题同rubric对照、批次执行完整、无新增重大事实/范围/引用错误、边界行为不倒退、执行控制合同通过；最终完整性/数值覆盖的改善不能只用更高Recall替代。首批6题不作显著性或泛化声明。
