# Design

Use `finrag.serving` for ingestion, DB/ANN/BM25, runtime and API. Reuse source parser/chunker, validated planner, fusion, source context, API billing, answer format and trace. Frozen `finrag` schema remains unchanged; isolated `finrag_live` namespace holds only serving data. Bootstrap selected existing index without re-embedding. One filing transaction updates sources/chunks/inverted postings/corpus statistics; immutable identity prevents torn generations and stale evidence caches. Memory bounded by one document and fixed API batches.

Implement evidence-objective replanning as an optional validated pass, independently testable using existing plans and identical SQL upper bounds. It may be disabled in serving config; comparison does not promote a winner automatically. BM25 uses lowercase English alphanumeric tokens, no stemming, k1=1.2/b=.75; term/corpus statistics are stored in PostgreSQL, updated atomically. SQL candidate scoring uses inverted index, not a Python full scan.

Only one ANN type per serving chunks table. Dedicated maintenance builds concurrently; HNSW strict iterative scan / IVFFlat relaxed iterative scan with outer sort. Raw distance ascending inner order; exact uses expression to bypass ANN. Filter and statement timeout stay inside transaction. Dimension/model locked to index configuration; changing models requires another namespace/version, not mixed vectors.

CrossEncoder is Voyage rerank-3-lite API (same credentials), not embedding similarity; conservative $0.02/M processed tokens including repeated query. LLM option reuses source-line grader. Dedicated scores are used only for ordering, not fabricated support labels. Local API optional FastAPI/uvicorn; localhost bind only, bounded in-flight queries, ingestion via trusted CLI; shared Budget ledger avoids double-spend races. One connection per admitted request avoids sharing mutable transaction state, no pool until measured need.

Validation order: offline contracts → isolated DB transaction/ANN tests → bootstrap and small provider pilot → 20-query fixed-budget comparison → end-to-end sample answers → docs and remaining production gates. All paid work shares original ledger with conservative stop threshold $1.60 initially; never consume budget just because available.

Implementation outcome: active finrag_live_ready; initial finrag_live retained for rollback after automatic review rejected schema deletion. Canonical bootstrap reparses checksum-verified raw HTML and compares chunk payloads before reusing vectors, avoiding legacy parser block generations. v4 task compiler uses original SQL budget; same 342 calls per arm. BM25 candidate improves final context to71.53%; regroup/CrossEncoder not promoted. Full report and remaining release gates: reports/serving/README.md.
